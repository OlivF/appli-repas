# Desserts, fruits, fromages : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** autant de desserts, fruits, fromages, laitages et entrées qu'on veut par repas, chacun
pour qui en mange, comptés dans les courses et le frigo, jamais touchés par la proposition auto.

**Architecture :** la sorte est une colonne de la recette (`recipes.course`) ; chaque carte la
reçoit par jointure (`WeekCard.course`). Les quatre endroits qui appliquent « un plat par
personne » (`set_planned_meal_eaters`, `add_planned_meal`, `moveEaters`, le planner) ne regardent
que les plats ; `add_planned_extras` ajoute ou fusionne les plats légers en une transaction.

**Tech Stack :** Supabase (Postgres, pgTAP), Next.js 16 App Router, Vitest, Playwright, dnd-kit.

**Spec :** `docs/superpowers/specs/2026-11-20-desserts-design.md`

## Global Constraints

- Branche `desserts` depuis `main` (34a976c) ; A puis B enchaînés, un commit par partie, PR vers `main`.
- Migrations `0015_meal_courses.sql` (schéma, fonctions, référentiel) et `0016_light_catalog.sql` (générée).
- Types : `supabase gen types typescript --local --schema public > lib/supabase/database.types.ts`.
- Fonctions : `security invoker`, `set search_path = ''`, `revoke … from public, anon`, `grant … to authenticated`.
- `course` : `starter`, `main`, `dessert`, `fruit`, `cheese`, `dairy` ; ordre des puces du bas : `dairy`, `fruit`, `cheese`, `dessert`.
- `UNSCALED_COURSES = ["dessert", "fruit", "cheese", "dairy"]`.
- Interface : tutoiement, zéro jargon, charte `/design`, composants existants, pas de style ad hoc.
- Tests : `supabase test db`, `docker compose exec web npm test`, `docker compose exec web npx tsc --noEmit`, `docker compose run --rm e2e`, `docker compose exec web npm run build`.

## Review Focus

- Un yaourt ajouté à « tous les dîners » sur un repas où il est déjà pour Otis seul → fusion, pas
  de seconde carte (pgTAP `add_planned_extras` + Vitest `extrasToAdd`).
- « Relancer » avec des plats légers non verrouillés → toujours là après (pgTAP
  `save_week_proposal` + e2e).
- Changer la sorte d'une recette déjà au menu → la carte change de rangée sans erreur
  (`buildBoard` lit `card.course` ; Vitest).
- Glisser un plat sur un autre quand le repas a des puces → seuls les plats s'échangent, les puces
  restent (`swap_planned_meals` refuse une carte légère ; pgTAP).
- Semaine en cours, « Tous les dîners » ouvert un mercredi → lundi et mardi non visés (Vitest
  `extrasToAdd` avec `fromDay`).
