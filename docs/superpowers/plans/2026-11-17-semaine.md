# Semaine (étape 2, partie 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Planning de la semaine : proposition automatique, grille / jour par jour, glisser-déposer, verrous, « Autre idée », Bibliothèque.

**Architecture:** Schéma + RLS dans `0005_week_plans.sql`, écritures multi-lignes par fonctions SQL `security invoker`. Algorithme pur dans `lib/planner.ts` (Vitest), dates dans `lib/week.ts`. Server Actions dans `app/(app)/semaine/actions.ts` qui chargent, calculent et renvoient l'état de la semaine ; un composant client tient l'état et anime.

**Tech Stack:** Next.js 16 (cacheComponents), Supabase (RLS, pgTAP), Tailwind 4, shadcn/ui, framer-motion, `@dnd-kit/core` 6.3, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-semaine-design.md`

## Global Constraints

- Interface en français, au tutoiement ; code et tables en anglais.
- Toute table métier : `household_id` + RLS ; aucun accès `anon`.
- Schéma seulement dans `supabase/migrations/*.sql` ; types régénérés : `supabase gen types typescript --local --schema public > lib/supabase/database.types.ts`.
- Aucun style ad hoc : nouvelles pièces d'abord sur `/design`.
- npm dans le conteneur : `docker compose exec -T web npm …`.
- Un seul commit pour cette partie, sur la branche `etape-2-semaine`, puis push + PR.

## Review Focus

- Semaine dans l'adresse invalide (`?semaine=bidule`, un mardi) : on retombe sur la semaine prochaine / le lundi de cette semaine (Task 2, `parseWeekParam`).
- Membre exclu d'une recette « pour tous » : jamais servi avec (Task 3, test `respecte les exclusions`).
- Relancer avec toutes les cartes d'un créneau verrouillées : rien n'est ajouté à ce créneau (Task 3).
- Recette supprimée alors qu'elle est planifiée : la carte disparaît, le créneau redevient vide (Task 1, pgTAP).
- Créneau retiré des réglages après la proposition : ses cartes ne s'affichent plus et « Relancer » les supprime (Task 5, `buildBoard` ; Task 1 via `save_week_proposal`).

### Task 3: Algorithme `lib/planner.ts`

**Files:** Create `lib/planner.ts`, `lib/planner.test.ts`.

**Interfaces — Produces:**
```ts
type Protein = string; // "volaille" | "boeuf" | "porc" | "agneau" | "poisson" | nom normalisé
type PlannerMember = { id: string; diets: Diet[] };
type PlannerRecipe = { id: string; meal_types: MealType[]; diets: Diet[]; excludedIds: string[];
  favorite: boolean; minutes: number; protein: Protein | null };
type PlannerSlot = { day: number; meal_type: MealType; member_ids: string[] };
type PlannerCard = { day: number; meal_type: MealType; position: number; recipe_id: string;
  member_ids: string[]; locked: boolean };
function mainProtein(ingredients: { name: string; aisle: GroceryAisle }[]): Protein | null;
function canEat(recipe: PlannerRecipe, member: PlannerMember): boolean;
function proposeWeek(input: { slots: PlannerSlot[]; members: PlannerMember[];
  recipes: PlannerRecipe[]; locked: PlannerCard[]; seed: number }):
  { cards: PlannerCard[]; unfed: { day: number; meal_type: MealType; member_ids: string[] }[] };
  // cards = nouvelles cartes seulement (locked: false), positions après les verrouillées
function nextIdea(input: { card: PlannerCard; cards: PlannerCard[]; members: PlannerMember[];
  recipes: PlannerRecipe[]; tried: string[]; seed: number }): string | null;
```
Règles, notes et repli : spec, section Algorithme (valeurs exactes : favori +3 ; semaine +2 si ≤ 30 min sinon −1 par quart d'heure entamé au-delà ; week-end +2 si ≥ 45 min ; famille −3 ; petit-déj répété −4 ; écart 0–1,5 par hachage).

- [ ] Tests (petit jeu de recettes + foyer de test complet construit dans le test) : une recette pour tous si elle existe ; sinon 2 cartes (la plus couvrante + une pour le reste) ; 3 cartes si nécessaire ; respecte les exclusions ; pas de répétition hors petit-déj ; petit-déj ≤ 2 ; repli : recette servie le plus tôt, jamais la veille/le lendemain ; membre sans recette possible → `unfed` ; verrous : membres servis retirés, recette verrouillée comptée comme servie, créneau entièrement verrouillé sans nouvelle carte ; même graine → même résultat, graines 1..5 → au moins 2 résultats différents ; favori préféré à égalité ; lundi préfère 20 min à 60 min, samedi l'inverse ; pas deux jours de suite la même famille quand on peut l'éviter ; foyer de test : chaque présent de chaque créneau a exactement une carte qui lui convient ; `mainProtein` (« Blancs de poulet » → volaille, « Tranches de jambon blanc » → porc, « Pavés de saumon » → poisson, aucun boucherie → null) ; `nextIdea` différente de l'actuelle et des essayées, convient aux mangeurs, `null` quand tout est essayé.
- [ ] Implémenter ; `docker compose exec -T web npx vitest run lib/planner.test.ts` → vert.
