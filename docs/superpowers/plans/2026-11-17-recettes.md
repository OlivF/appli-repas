# Recettes (étape 2, partie 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recettes par foyer + catalogue commun, grille `/recettes`, fiche avec quantités recalculées, formulaire d'une page.

**Architecture:** Schéma et RLS en migrations SQL ; écritures multi-tables par fonctions SQL `security invoker` (`save_recipe`, `copy_recipe`) appelées depuis des Server Actions ; logique pure (formulaire, quantités, filtres, qui mange quoi) dans `lib/recipes.ts`, testée par Vitest ; écrans dans un groupe de routes `app/(app)` qui porte la barre d'onglets.

**Tech Stack:** Next.js 16 (App Router, cacheComponents), Supabase (Postgres 17, RLS, pgTAP), Tailwind 4, shadcn/ui + radix-ui, framer-motion, lucide-react, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-recettes-design.md`

## Global Constraints

- Textes de l'interface en français, au tutoiement ; code, tables, colonnes en anglais.
- Toute table métier porte `household_id` + RLS ; aucun accès `anon`.
- Schéma uniquement dans `supabase/migrations/*.sql` ; types régénérés par `supabase gen types typescript --local --schema public > lib/supabase/database.types.ts`.
- Aucun style ad hoc : chaque écran n'utilise que des composants montrés sur `/design`.
- Commandes npm dans le conteneur : `docker compose exec -T web npm …`.
- Un seul commit pour toute cette partie (choix de l'utilisateur), à la fin.

## Review Focus

- Quantité saisie avec une virgule (« 1,5 ») : lue comme 1.5 (Task 4, test `parseRecipeForm`).
- Ligne d'ingrédient laissée vide dans le formulaire : ignorée, pas d'erreur (Task 4).
- Ingrédient sans quantité (« Sel ») sur la fiche : affiché sans quantité quel que soit le curseur (Task 4, `formatIngredientQuantity`).
- Adresse d'une recette du catalogue déjà copiée : renvoie vers la copie (Task 8).
- Recherche « creme » : trouve « Crème » (Task 4, `matchesSearch`).

  - `normalizeText(text: string): string` ; `matchesSearch(recipe: {title: string; ingredientNames: string[]}, query: string): boolean`.
  - `RecipeFilters = {query: string; mealTypes: MealType[]; diets: Diet[]; batch: boolean; favorites: boolean}` ; `filterRecipes<T extends FilterableRecipe>(recipes: T[], filters: RecipeFilters): T[]` ; `filtersFromSearchParams(params: URLSearchParams): RecipeFilters` ; `filtersToSearchParams(filters: RecipeFilters): URLSearchParams` (clés `q`, `repas`, `regime`, `avance`, `favoris`).
  - `memberEatability(recipe: {diets: Diet[]}, member: {id: string; diets: Diet[]}, excludedIds: string[]): "ok" | "excluded" | "diet"` ; `describeEaters(members: {first_name: string}[], outIds: string[]): string` (« Pour tout le monde », « Sauf Marie-Laure », « Sauf Marie-Laure et Otis », « Pour personne »).

- [ ] **Step 1: Tests** (`lib/recipes.test.ts`) :

  - `memberEatability` : membre céto sur plat non céto → `"diet"` ; exclu → `"excluded"` ; sinon `"ok"`.
  - `describeEaters` : les quatre libellés.
